# Veriqorn Community v0.2.38

- Fix API key creation in Settings: the backend now returns the complete shared response contract, including `lastUsedAt: null`, so the UI displays the newly generated key instead of reporting a failure after saving it.
- Validate the create response against `createdApiKeySchema` on both sides, and convert the optional local expiry date to an ISO timestamp before sending it.
- Add a PostgreSQL regression covering normal login, creation with and without an expiry, hashed storage, authenticated use, listing without the raw token, and revocation.

## Upgrade

Upgrade backend and frontend together. Keys created during a failed UI attempt remain listed and can be revoked normally; their raw values cannot be recovered. Create a new key after upgrading. Existing storage and license requirements remain those documented for [v0.2.35](v0.2.35.md).
